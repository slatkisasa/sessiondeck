# Domain docs

## Before exploring

Read GLOSSARY.md at the repository root and ADRs under docs/adr/
that touch the area being explored.

If these files do not exist, proceed silently. The domain-modeling
skill creates them when terms or decisions are resolved.

## Layout

This is a single-context repository:
- GLOSSARY.md: shared domain vocabulary.
- docs/adr/: architectural decision records.

## Vocabulary

Use glossary terms in issue titles, proposals, hypotheses, and test names.
If a needed concept is absent, reconsider the term or note the gap for
domain-modeling.

## ADR conflicts

Explicitly flag proposals that contradict an existing ADR, identify the
ADR, and explain why the decision merits reopening.
